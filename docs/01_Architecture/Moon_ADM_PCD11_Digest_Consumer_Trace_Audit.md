# Moon ADM PCD-11 — Selected Input Digest Consumer Trace Audit

- Date: 2026-10-15
- Status: Audit complete; policy decision remains open
- Scope: Static code/test/documentation trace against the uploaded `Orion_1013.zip` snapshot
- Runtime/API calls: None
- Source snapshot: commit `fea05ba` as represented by the uploaded archive

## Findings

### 1. Production usage

`selected_input_digest` is generated by `assess_adm_monthly_dataset()` in `src/orion/frameworks/moon/adm_data.py` and stored on `ADMMonthlyDataAssessment`.

Within `src/` and `tests/`, the only direct references found are:

- generation in `assess_adm_monthly_dataset()`;
- lowercase SHA-256 format validation in `ADMMonthlyDataAssessment.__post_init__()`;
- `tests/orion/frameworks/moon/test_adm_data.py::test_monthly_assessment_digest_is_stable_and_binds_selected_values`.

`src/orion/frameworks/moon/adm_workflow.py` returns the assessment as part of `ADMDataWorkflowResult`, but does not independently persist, compare, or consume the digest. No signal assembler, runtime, governance approval service, or event consumer uses the digest in this snapshot.

### 2. Digest payload

The digest is SHA-256 over canonical JSON (`sort_keys=True`, compact separators, UTF-8, `ensure_ascii=False`, `allow_nan=False`) containing selected observations' `symbol`, `field`, `observed_at`, `value`, `source`, `currency`, and `metadata`.

The Alpha Vantage adapter populates `metadata["retrieved_at"]`; because the complete metadata mapping is included, retrieval time affects the digest. This is a confirmed behavior, not evidence of a defect by itself.

### 3. Existing test coverage

The current digest test proves:

- repeated assessment over identical fixture input yields the same digest;
- changing a selected value changes the digest.

It does not separately test whether changing only `retrieved_at`, source metadata, currency, or metadata key ordering should change the digest. Those outcomes are currently implied by the implementation rather than documented as an explicit contract.

### 4. Decision needed

PCD-11 currently says to fingerprint canonical selected observations while also preserving adapter provenance. Before changing code, explicitly choose one of these semantics:

- **Selected observation identity:** include only fields that define the selected market observation; keep retrieval/provenance metadata outside this digest or in a separate provenance digest.
- **Full selected-input batch identity:** include all selected observation fields and provenance metadata, including `retrieved_at`; document that two retrievals of identical market values may have different digests.

Either can be valid. The current implementation behaves like the second option. Since no downstream consumer depends on digest equality in this snapshot, there is no current runtime compatibility dependency to migrate, but future persistence, caching, replay, or approval binding would make the choice consequential.

## Recommendation

Do not change implementation yet. Record the digest's intended semantics in PCD-11, then add focused tests for metadata-only changes and deterministic metadata canonicalization. Keep durable snapshots, runtime approval binding, and strategy activation out of scope until separately approved.
